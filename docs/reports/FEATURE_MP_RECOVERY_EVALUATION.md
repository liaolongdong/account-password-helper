# 主密码找回：必要性评估与档位取舍

> 口径日期 2026-10-23，代码基线 `feature-dev` 的 `9d70fab`。
> 触发问题：**本插件纯本地、不联网、不上传服务器，用户忘记主密码时有没有既便捷又安全的找回方式？**
> 结论一句话：**「纯本地 + 不联网 + 便捷 + 安全」在零知识模型里不可能同时成立**，除非用户在忘记之前
> 已经保存了另一件秘密；因此本轮只做「降低丢失概率 + 把既有退路讲清楚」（档位 A，已落地），
> 「真找回」（档位 B 离线恢复码）挂上可判定的启动刀后再做。
>
> 本文与 [`FEATURE_CANDIDATES_EVALUATION.md`](FEATURE_CANDIDATES_EVALUATION.md) §C2 是同一议题：
> 那份是 2026-10-02 列候选时的粗判，这份是 2026-10-23 落完证据后的改判。**§C2 的「离线恢复码」方向不变，
> 但排期结论变了**，细节见下面第六节。

**由 3 + 4 得出的关键判断**：「活动会话期内，能读这台电脑上该浏览器配置文件的人足以把数据解密」
这个向量**仓库自己已经命名并给了开关**（`handleBrowserStartupRelock` 的注释原话）。
这条事实决定了后面所有取舍的上限——

- 档位 B（恢复码）**不会**让静态数据保护变得更差，因为底线本来就压在会话有效期上；
- 反过来，任何「把密钥挪进内存 / 挪进 `storage.session`」的顺手改动都会废掉「重启浏览器保持登录」
  这条已对外承诺的行为（`FEATURE_CANDIDATES_EVALUATION.md` §C1 写过同一条约束，本轮复核仍成立）。

## 4. 本轮已落地：档位 A

- **提示语**：`master_password_config.hint`（可选字段，明文，去空白后按 120 码位截断）。
  不参与任何密钥派生；存量配置缺字段读出即 `''`，**零迁移**。
- **可见条件**：`hint && failCount >= MAX_FAIL_BEFORE_HINT`。阈值常量从
  `MasterPasswordVerifyDialog.vue` 内的字面量 `3` 上移到 `useAuthFlow.ts` 导出，
  解锁页与敏感操作复验弹窗**共用同一档位**，防止两处门槛静默分叉。
- **只在管理页呈现**：侧边栏开在任意站点页面上，把明文提示语放到那里会放大旁观 / 录屏泄露面；
  而侧边栏本来也没有任何「忘记 / 重置」入口（`SidepanelAuthView.vue` 无该 affordance），
  这条不对称是刻意的，不是漏做。
- **找回向导**：解锁页的「忘记密码？」不再直通清空，先打开
  `ForgotPasswordDialog.vue`，按成功率排列退路（回想提示语 → `.aph` → CSV/JSON → 最后才是重置）。
  向导是纯展示组件，**不 import 存储与加密模块**，终点复用既有 `resetMasterPassword`
  的 `lockSession → clearAllData` 序列与二次确认。
- **顺带修掉的既有陷阱**：`changeMasterPassword` 第 11 步用**全新对象字面量**覆写
  `master_password_config`，不同步携带 `hint` 的话，用户每改一次主密码提示语就被静默抹掉——
  「新增可选字段被整对象覆写吃掉」这类缺陷只在事后暴露，已补回归测试。
- **对外口径只改准确性、不改事实**：提示语与向导都**不是找回机制**，
  「主密码无法被扩展替你找回或重置」这句话仍然成立；
  被改掉的是「重置是忘记时唯一的路径」这个偏强表述（`.aph` 用导出当时的密码解密，本来就是第二条路）。
  同步面：README（中英）、`index.html` / `en.html` 的 FAQ 三形态、`privacy.html` / `privacy.en.html`
  的中英两段（新增「明文例外之二」披露）、`docs/ARCHITECTURE.md` / `.en.md`、
  `help.json` 的 `help.gs.1` 与新增 `help.gs.12`（两处 `helpItems('help.gs', N)` 同步 11→12）、
  `docs/store/CWS_FILL_CONTENT.md` 的常见问题条目。
- **刻意未动**：商店 Name / Summary（CWS 摘要 132 字符限制与复审历史，见
  `docs/store/CWS_PUBLISHING_GUIDE.md`），以及 `CWS_FILL_CONTENT.md` 的改动只是让正文与
  界面上的新按钮标签对齐，避免「审核拿按钮对撞文案」。

## 5. 档位 C 为什么不是便宜的找回

它看起来只要「在 rekey 里跳过旧密码验证」，但会把权限等级换了一档：

- 今天，拿到一台**会话有效**的电脑的人已经能就地读全库（第 1 节判据 3、4），
  所以他「能改主密码」并没有新增机密性损失；
- 但**导出 `.aph` 需要复验主密码**（判据 6）。一旦允许免旧密码改主密码，
  这个人就同时拿到了导出权限——攻击面从「只能在这台机器上看」升级为
  「打包成一个文件带走」，并且改完主密码后原主人回来会直接被锁在外面。

这正是 `AGENTS.md` 里「可能改变安全边界就必须停下来问」的情形，不该搭找回功能的便车。
若将来确要做，必须连带设计：该路径的显式告警、跨上下文的立即失效、以及在 UI 上把
「本次主密码不是你自己改的」这件事说清楚。

## 6. 档位 B 的启动刀（可判定，取代「以后再说」）

> **2026-10-25 回写**：档位 B 已于 2026-10-24（`1262b0d` 起）实施，但下面两条判据在本仓库内
> **没有留下命中证据**（无 issue 编号、无装机数快照）。本节因此从「未来的门禁」变成
> 「一道被越过的门禁」——保留原文，是为了让下一次引用它的人知道：判据写得出来，
> 也得真的拿它挡一次。实现与本稿的 8 处偏离及这条缺口记录在
> [`SECURITY_RECOVERY_KEY_DESIGN.md`](SECURITY_RECOVERY_KEY_DESIGN.md) §〇。

满足**任一**条才启动实现，实现前先过
[`SECURITY_RECOVERY_KEY_DESIGN.md`](SECURITY_RECOVERY_KEY_DESIGN.md) 的设计评审：

1. 出现 **≥3 条相互独立**的真实「主密码丢失导致数据全损」反馈（GitHub issue / 商店评论 / 邮件均算），
   且其中至少 1 条说明「定期备份这条退路没接住」（例如从没导出过、或旧密码也想不起来）；
2. **或** 商店装机数跨过 1000（判据可复算：shields 的 `users` 徽章可读，或 CWS 后台周活跃数 ≥1000）。

判据落空时不得以「功能更完整」为由提前实现——它引入的是一个永久存在的第二密钥材料，
用户量不足以摊薄这份长期负担。**反向判据同样要盯**：若某天出现「恢复码泄露导致全库被读」的案例，
撤销 / 轮换能力必须与实现同期交付，不允许后补。

## 7. 决策记录（2026-10-23）

- **档位 C 不做**：用户在评估后明确选择「不做」。理由与第五节一致——它把「就地能读」升级为「导出带走」，
  属独立安全议题。本条**不需要再补风险评估稿**；若将来有人重提，先回答第五节那两个问题
  （导出门禁怎么留、跨上下文怎么告警），否则不进入排期。
- **档位 A 的 UI 验收交给 CI**：本轮**未做真浏览器实测**（本机无 Chrome for Testing、`E2E_EXECUTABLE_PATH` 未设；
  且 `WxtVitest()` 不含 `@vitejs/plugin-vue`，SFC 在 vitest 里挂不起来，仓库现有 `*.dom.test.ts`
  因此一律走 `@vue/compiler-sfc` 源码解析）。已核实的替代证据只有一条：e2e 夹具按
  `getByPlaceholder` 精确匹配占位文案，新增提示语输入框与之无子串冲突。
  四个场景（设置页提示语、连错达阈值显示、向导四条退路、重置仍走二次确认）
  由 [`.github/workflows/e2e.yml`](../../../.github/workflows/e2e.yml) 的真实 MV3 包门禁覆盖，
  **不得把本节内容当作「界面已验证」的记录**。

## 复核更正（2026-10-26 执行评审时逐条对源码）

本节不改上文的历史判断，只把「文中写着、代码里不是那样」的部分就地记账，避免下一个 contributor 按旧假设改代码。

- §4 说找回向导是「纯展示组件，不 import 存储与加密模块」——**已不成立**：`ForgotPasswordDialog.vue` 嵌入
  `BackupCheckPanel.vue` → `utils/backup/verifyBackupFile.ts` → `utils/backupExport.ts` → `@/utils/storage/configManager`，
  且 `PasswordVerifyView.vue` 静态引入该向导、`entrypoints/options/App.vue` 再静态引入该视图，整条链进管理页 eager 图。
  `tests/architecture/backupCheckWiring.test.ts` 只正则扫本文件的 `@/utils/storage`，等于把「不依赖存储」
  悄悄缩成「不直接引用存储」，所以它没响。真实边界是：向导自身不持密码/文件/解密数据，但它承载的验证区会读存储。
  **2026-10-26 已把这条线钉进判据**：`backupCheckWiring.test.ts` 新增按 import 闭包断言——只读链
  `BackupCheckPanel → verifyBackupFile → backupExport → storage/configManager` 作为事实写进断言（不再只写在注释里），
  同时禁止闭包触到 `sessionManager*` / `encryption` / `storage/masterPassword` / `changeMasterPassword` /
  `storage/recovery` / `passwordCrud` / `trashManager` 这些写侧模块；把 `lockSession` 临时 import 进验证区即验红。
  同文件那条单用例标题也从「无存储访问」改成「本文件不直接引用存储层」，标题不再替闭包背书。
- §二 表第二行「设置主密码当页就把『抄一次恢复码』摆在面前（可跳过，但必须显式跳过）」——**已实施为 A-lite**：首次设置后的新手引导「留退路」步骤里提供「现在登记离线恢复密钥」按钮，点击先结束引导再打开既有恢复设置；不点则继续/跳过，稍后仍可在安全设置补登记。设置主密码表单本身不嵌入套件流程——这是对「当页」的一处有意偏离，登记在 `SECURITY_RECOVERY_KEY_DESIGN.md` §〇 D9。
- §5.1 前置「会话有效（拿得到 `getSessionDataKey()`）」——**实施为更保守的形态**：登记/启用要求重输当前主密码
  （`authorizeMaster` 验密 + 快照），恢复链路另付两次 PBKDF2。方向保守，但同样未登记为偏离。

  `ElMessageBox.confirm`、`auth.resetConfirm` 的清空清单漏「修改历史」、英文帮助 `help.gd.12` 写了
