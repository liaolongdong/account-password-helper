## 0. 一分钟模型

一条账号能不能出现在你眼前、能不能填进这个登录框，由**两道门串联**决定：

```
可见 ∧ 可填充  =  主机门 resolveMatchTier(页面主机, 条目网址, 档位)
                 ∧ 端口门（环回主机在 loose 下用 matchesPortForLocalDev；其余用 matchesPortScope）
```

- **主机门**回答「哪些**主机**算本站」，返回层级 `tier`：`0` 精确（含环回别名）/ `1` 通配条目 / `2` 同主域 apex / `3` 同主域其他子域 / `4` 网址为空 / `-1` 不属于本站。这个数字同时就是排序权重。
- **端口门**回答「同一主机上不同端口的账号要不要互相隔开」，取值 `loose` / `strict`（持久化）加一个只存在于显示层的 `relaxed`。
- **第三条轴只管先后**：列表排序按「与当前站点的关联度」（[`siteRankOf`](../../utils/domain.ts#L769)），恒按最宽口径取层级，**与用户所选档位无关**——档位管「看不看得到」，关联度管「谁排在前面」。见 §2.4。
- 两道门由 [`matchesSiteEndpoint`](../../utils/domain.ts#L1028) 合成，**五个入口共用它**：侧边栏「本站」、内联下拉、一键填充、排序优先级、Popup「此站已有账号数」。以前这四处各自复制分支、且复制得不完整（环回少抄主机、Popup 少抄端口），才会出现「下拉里有、侧边栏没有」和「两个入口结论相反」。
- 单调性：**`strict ⊆ loose ⊆ relaxed`**，且主机门只会因档位放宽而变宽；任何一档都不会把「主机不属于本站」的条目带进来。

## 2. 主机轴：三档真值表

### 2.1 公网页面（以当前页 `mail.qq.com` 为例，端口轴取默认 `loose` 且不比端口）

| 条目网址                                   | `off`（默认） | `wildcard` | `sameMainDomain` | tier       | 呈现                                                          |
| ------------------------------------------ | ------------- | ---------- | ---------------- | ---------- | ------------------------------------------------------------- |
| `mail.qq.com`、`https://mail.qq.com/login` | ✅            | ✅         | ✅               | 0 精确     | 无徽章，排最前                                                |
| `*.qq.com`、`https://*.qq.com/login`       | ❌            | ✅         | ✅               | 1 通配     | 「跨子域」徽章                                                |
| `qq.com`（apex）                           | ❌            | ❌         | ✅               | 2 主域名   | 「跨子域」徽章                                                |
| `music.qq.com`（兄弟子域）                 | ❌            | ❌         | ✅               | 3 其他子域 | 「跨子域」徽章                                                |
| （网址留空）                               | ✅            | ✅         | ✅               | 4 通用     | 排最后，不标来源                                              |
| `uat.example.com`、`fat.example.com`       | ❌            | ❌         | ❌               | −1         | 「全站」范围里才会出现，且降级为打开站点                      |
| `evil-qq.com`（前缀碰撞）                  | ❌            | ❌         | ❌               | −1         | 通配刻意用「注册主体相等」判定，不用 `endsWith('.qq.com')`    |
| 页面 `a.github.io`，条目 `b.github.io`     | ❌            | ❌         | ❌               | −1         | 共享托管后缀下是**不同租户**                                  |
| 页面 `a.github.io`，条目 `*.github.io`     | ❌            | ❌         | ❌               | −1         | 该通配的字面含义就是跨租户；要覆盖自己项目写 `*.me.github.io` |
| `localhost:3000`                           | ❌            | ❌         | ❌               | −1         | 环回别名只与环回折叠，不与公网折叠                            |

排序链：**tier 升序 → 收藏置顶 → 侧边栏排序字段**（默认 `lastUsedAt` 降序）。因此列表首条 = 一键填充的目标。

### 2.2 环回别名（本机三种写法 = 同一主体）

| 当前页主机       | 条目主机写法                                           | 结果                                                    |
| ---------------- | ------------------------------------------------------ | ------------------------------------------------------- |
| `localhost:3000` | `127.0.0.1:3000`、`[::1]:3000`、`::1:3000`             | ✅ tier 0（别名折叠）                                   |
| `127.0.0.1:3000` | `localhost:3000`                                       | ✅ tier 0                                               |
| `[::1]:3000`     | `localhost:3000`                                       | ✅ tier 0                                               |
| `localhost`      | `*.localhost`                                          | ❌（`off`）／ ✅ tier 1（`wildcard`、`sameMainDomain`） |
| `127.0.0.1`      | `*.localhost`                                          | ❌（`off`）／ ✅ tier 1（改前**任何档位都不命中**）     |
| `localhost`      | `myapp.localhost`                                      | ❌ 同机不同虚拟主机，不折叠                             |
| `localhost`      | `192.168.1.5`、`10.0.0.5`、`myapp.test`、`example.com` | ❌ 内网 IP 与公网主机不折叠                             |

折叠发生在**相等判定**这一层（[`canonicalSiteHost`](../../utils/domain.ts#L318)），不改 `getMainDomain` / `registrableScope`，所以远端主体永远不可能被折进 `localhost`。

### 2.3 排序关联度（与档位无关）

[`siteRankOf`](../../utils/domain.ts#L769) 给每条算一个排序权重，数值越小越靠前。**它不改变任何一条能不能出现，只改变它出现在第几行**：

| 权重 | 含义                                             | 例子（当前页 `localhost:3000` / `fat.example.com`）   |
| ---- | ------------------------------------------------ | ----------------------------------------------------- |
| 0    | 当前端点：主机相同（含环回别名）**且**端口对得上 | `localhost:3000`、`127.0.0.1:3000`、`fat.example.com` |
| 1    | 同主机、其他端口（本机另一个服务）               | `localhost:4000`、`127.0.0.1:5173`                    |
| 2    | 通配条目命中                                     | `*.example.com`                                       |
| 3    | 同主域 apex                                      | `example.com`                                         |
| 4    | 同主域其他子域                                   | `dev.example.com`、`uat.example.com`                  |
| 5    | 网址为空的通用条目                               | （留空）                                              |
| 6    | 与当前站点无关                                   | `github.com`、`qq.com`                                |

权重 1 只比 0 低一位：本机另一个端口上的服务，显然比陌生站点更相关——它曾排在无关站点之后（实测 `localhost:4000` 落在 `github.com` 后面），那正是「相关度高的排前面」被排反的地方。

链上顺序仍是 **关联度 → 收藏置顶 → 侧边栏排序字段**，所以关联度**压过收藏**：一个收藏过的 `github.com` 账号，现在会排在没收藏的 `dev.example.com` 之后（这是本次调整的目的，也是「全站」列表里最容易被察觉的变化）。

不变的是「本站」列表：默认 `off` 档下可见集只有权重 0（当前端点）与 5（留空通用）两类，相对顺序与调整前逐字一致，因此**内联下拉、一键填充、右键菜单取到的首条不变**。

### 2.4 主机归一口径

条目网址可以是完整 URL、`host:port`、纯域名、`*.domain`；一律先经 [`normalizeToHostname`](../../utils/domain.ts#L487) 归一为小写 hostname（端口与路径被剥掉，`:*` 也被剥掉，否则 `localhost:*` 会留下脏尾永远匹配不上）。大小写与首尾空白不敏感。

## 3. 端口轴

### 3.1 三种取值的规则

| 取值                          | 公网 / 内网主机                                                                                                                 | 环回主机（`localhost` / `127.0.0.1` / `[::1]`）                                                                                              |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `loose`（默认）               | **完全不比端口**：同主机的任何端口条目都可见                                                                                    | 比端口：条目写了端口就必须与当前页端口一致；未写端口或写 `:*` 一律可见；**当前页在默认端口（如 `http://localhost/`）时该主机的条目全部可见** |
| `strict`                      | 写了端口 → 只在同端口可见；**未写端口 → 只在该协议默认端口（http 80 / https 443）可见**（读作「门面地址」）；写了 `:*` → 恒可见 | 与公网同一条规则（环回特例取消）                                                                                                             |
| `relaxed`（仅显示层，不落盘） | 不比端口                                                                                                                        | 不比端口，但条目仍要先过主机门                                                                                                               |

### 3.2 环回主机 · `loose`（默认档）

当前页 `http://localhost:3000`：

| 条目网址                                                  | 可见 | 可填充 | 理由                                                               |
| --------------------------------------------------------- | ---- | ------ | ------------------------------------------------------------------ |
| `localhost:3000` / `127.0.0.1:3000` / `[::1]:3000`        | ✅   | ✅     | 别名 + 同端口                                                      |
| `localhost`（未写端口）                                   | ✅   | ✅     | 未写端口 = 不限端口                                                |
| `http://localhost/`                                       | ✅   | ✅     | 同上（`URL.port` 为空）                                            |
| `localhost:*`                                             | ✅   | ✅     | 显式跨端口条目                                                     |
| （网址为空）                                              | ✅   | ✅     | 通用条目，tier 4                                                   |
| `localhost:4000` / `127.0.0.1:5173`                       | ❌   | ❌     | 端口不符；**芯片计数 +1**，点开芯片可临时显示（届时可见 ❌可填充） |
| `myapp.localhost:3000`、`example.com`、`example.com:3000` | ❌   | ❌     | 主机门挡住（改前这几条是 ✅，就是本次修的缺陷）                    |

当前页 `http://localhost/`（无端口）：同主机条目全部可见（含 `localhost:4000`），外站条目仍然 ❌。

### 3.3 公网主机 · `strict`

当前页 `https://example.com:8443`：

| 条目网址                               | `loose` | `strict` | 说明                                                      |
| -------------------------------------- | ------- | -------- | --------------------------------------------------------- |
| `example.com:8443`                     | ✅      | ✅       | 同端口                                                    |
| `example.com` / `https://example.com/` | ✅      | ❌       | 门面地址只在默认端口出现                                  |
| `example.com:*`                        | ✅      | ✅       | 显式跨端口                                                |
| `example.com:9090`                     | ✅      | ❌       | 别的服务                                                  |
| `https://example.com:443`              | ✅      | ❌       | `strict` 用文本口径认字面写了的 `443`，不与页面 `8443` 混 |
| （空）                                 | ✅      | ✅       | 通用条目                                                  |

### 3.4 `relaxed` 的边界（重要）

- 只影响 `domainFilteredPasswords`（列表可见性）；`notFillableIds`、行点击/回车分派、排序沉底、Popup 计数、内联下拉与一键填充**一律仍用持久化策略**。
- 因此被 `relaxed` 带出的「同主机其他端口」条目：标 `其他端口` 徽章、紧跟当前端点之后（权重 1，仍在精确条目之后）、只提供复制与「打开站点」，绝不成为一键填充的首条。
- 芯片在 `relaxed` 状态必须继续可点（用于收回），此时条数计数归零。

| 一键填充 / 右键菜单填充      | 同内联下拉（`sortMatchesForDomain`）                                                                       | 同上                                                          | —                                                           | 取**首条**，因此「首条必属当前端点」是硬约定                                   |
| Popup「此站已有账号数」      | `matchesSiteEndpoint`                                                                                      | 0                                                             | —                                                           | **排除网址为空的通用条目**（它不算「此站」的账号），与侧边栏可见集口径有意不同 |
| 自动保存 / 判重              | [`autoSaveManager`](../../utils/storage/autoSaveManager.ts)：`hostMatchScore` + 端口门（仅 `strict` 参与） | —                                                             | 弹窗在跨子域/跨端口命中时注明「将更新 xxx 的同名账号」      | 见 §7                                                                          |

## 6. 管理页的「按站点筛选」

筛选栏第二个下拉（`utils/siteUtils.ts`），候选由条目网址**自动汇总**，不需要维护第二套结构。

| 规则                                                                             | 行为                                                                                                         |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 分桶键                                                                           | `normalizeToHostname` 归一 → `canonicalSiteHost` 折叠：**只按主机分桶，端口不进键**                          |
| `localhost:3000` / `127.0.0.1:4000` / `[::1]:5173` / `localhost:*` / `localhost` | **同一桶 `localhost`**（与匹配、排序同一套站点事实；改前是三个桶，勾 `localhost` 看不到 `127.0.0.1` 的条目） |
| `myapp.localhost`、`192.168.1.5`、公网主机                                       | 各自独立成桶，**不**折进 `localhost`                                                                         |
| `https://x.com/login` 与 `x.com`                                                 | 同桶（路径与查询不参与）                                                                                     |
| `*.qq.com`                                                                       | 独立桶，保留 `*.` 前缀（它是「适用范围」而不是某个站点）                                                     |
| 网址留空 / 只有空白 / 只有斜杠                                                   | 末位固定的「（无网址）」哨兵桶，**只在被勾选时参与结果**                                                     |
| 畸形网址（`http://`、`not a url`）                                               | 各成一个候选桶（归一残值），既不进哨兵桶也不被真实站点带出                                                   |
| 与跨子域档位、端口档                                                             | **完全无关**：筛选桶是库结构视图，不该随设置弹窗漂移                                                         |
| 多个选中站点之间                                                                 | 或关系（命中任一即保留）；与标签、关键词、只看收藏叠加为 AND                                                 |
| 行内计数                                                                         | 按**全库**条目数，与当前筛选结果无关                                                                         |

候选的展示分工（`components/options/SearchFilterBar.vue`）：

- **别名进标签**：`localhost（含 127.0.0.1 / ::1）`（别名取归一后的主机串：`[::1]:5173` 归一为 `[::1]`，裸写 `::1` 因不是合法主机而原样保留）。折叠后 `127.0.0.1` 不再是可勾选项，看不见就等于筛不到；顺带让键入 `127` 也能搜到这一桶。
- **端口分布进悬停 title**：`localhost（含 127.0.0.1） · 端口 3000 / 4000 / 5173 / *`。面板宽度按最长 label 量出，把端口串塞进 label 会让整列候选被最活跃的那一桶挤窄。
- 只在**真的发生折叠/写了端口**时才产出这些提示；单一写法且没写端口的桶仍是光秃秃的 hostname。
- 判定两侧同口径：条目侧经 `siteKeyOf` 折叠，选中侧也折叠，所以非 UI 路径传进来的别名串（测试、将来的深链）命中的是同一桶，不会筛出一片空集。选中集本身不落盘，切页面即清。

| UI 元素                                       | 出现条件                                                                             | 文案 key                                             |
| --------------------------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------- |

## 8. 自动保存与「改哪一条」的归属

| 环节               | 口径                                                                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 条目网址写入形态   | `location.host`：**含非默认端口**（`localhost:3000`、`192.168.1.1:8080`），协议默认端口被浏览器省略；同时另存 `protocol` 供端口判定                            |
| 判重（主机维度）   | 用户名相同 **且** 主机相等或互为父子域 → 视为「更新这条」；与主机档位、与环回别名**都无关**（`127.0.0.1:3000` 登录不会覆盖 `localhost:3000` 那条，会各存一条） |
| 判重（端口维度）   | `strict` 下端口参与归属：非默认端口登录只更新同端口条目，绝不拿它覆盖别的端口的同名条目；`loose` 下端口不参与（历史行为）                                      |
| 黑名单             | 无端口条目屏蔽该 hostname 及子域**所有端口**；写了端口的条目只屏蔽该端口                                                                                       |
| 域名规则（白名单） | 规则为空匹配所有非黑名单域名；含端口的规则只精确匹配 host+port                                                                                                 |

## 9. iframe 与跨帧边界

| 场景                                                                      | 结果                                                                                                 |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 顶层与帧**同注册主体**（`login.example.com` 帧在 `app.example.com` 顶层） | 允许帧委托填充与内联下拉                                                                             |
| 顶层与帧不同主域（含 `evil.github.io` vs `victim.github.io`）             | 帧内下拉返回空列表（不泄露账号存在性，也不触发解锁提示）                                             |
| 顶层 `http://127.0.0.1:3000`，帧 `http://localhost:3000`                  | **视为不同主体**：别名折叠只作用于账号列表的主机门，`isSameMainDomain` / `registrableScope` 刻意不折 |

## 10. 典型场景配方

| 你想达成                                                           | 怎么做                                                                                 | 代价                                                               |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 本机一套 dev 账号，前端 `:3000`、后端 `:4000`、网关 `:9000` 都能填 | 网址写 `localhost:*`（三种环回写法都认）                                               | 显式跨端口，只限本机，不会泄漏到公网站点                           |
| 本机同一账号还想在公网页面出现                                     | 网址留空                                                                               | 留空 = **任何站点**都可见可填，比 `:*` 宽得多，一般不该这么用      |
| `dev.` / `fat.` / `uat.` / `prod.` 严格隔离                        | 保持默认 `off`                                                                         | 无                                                                 |
| `qq.com` 的一条账号在所有子域可用                                  | 网址写 `*.qq.com` + 切到 `wildcard`；或直接把该条写成 `qq.com` + 切到 `sameMainDomain` | `wildcard` 逐条可控，`sameMainDomain` 一次放宽一片，后者弹窗有警示 |
| 公网一个域名上多个服务（`:8443` 后台 / `:9090` 面板）互不打扰      | 切到 `strict`，并把每条账号写成带端口的形式                                            | 只写了域名的账号会从非默认端口页面消失（芯片给出出口）             |
| 想临时看别的端口的账号再填进去                                     | 点端口芯片；然后在该行用复制 + 「打开站点」，或到该端口的页面再填                      | 放宽只放开显示，行内不会给你「填充」按钮，这是刻意的               |

## 11. 已知边界与坑（查阅时先看这里）

1. **`http://localhost:80` / `https://example.com:443` 这类「写了默认端口」的条目**：环回 `loose` 走 `extractPort`（WHATWG 会把默认端口抹成空串 → 按「未写端口」处理），`strict` 走 `declaredPortOf`（文本口径，认字面 `443`）。两档给出的理由不同，别依赖这种写法。
2. **`myapp.test`、`192.168.1.5`、`10.0.0.5` 不是环回**：`loose` 下它们**不比端口**（`:3000` 与 `:4000` 互相可见），与 `localhost` 的行为相反。要一致就开 `strict`。
3. **别名不扩张到三处**：iframe 同主域门、自动保存判重、`registrableScope` / `getMainDomain`。因此 `localhost` 与 `127.0.0.1` 在账号列表里是同一个家，在帧委托与判重里仍是两个站点。
4. **端口通配只在端口位**：支持 `localhost:*`，不支持 `*:3000`。自动保存写入的网址永远不含 `:*`（要跨端口复用只能手工录入）。
5. **环回页面头部不显示「本站 N 个账号」**；Popup 的那个数字又刻意不含空 URL 条目。两个数不等是设计，不是分叉。
6. **临时放宽期间**头部条目数会包含被带出的其他端口条目，而 Popup 不会（`relaxed` 只活在显示层，计数派生自展示策略）。
7. **`*.github.io` 这类覆盖公共后缀的通配条目命中不了任何站点**；要覆盖自己的项目写 `*.me.github.io`。
8. 条目网址为空 = 通用条目：任何站点都可见、可填，排序恒在最后。
9. 非 http 页面（`chrome://`、`file://`、扩展自身页）没有端口语义：端口轴按「处于默认端口」处理；`about:blank` / 新标签页取不到域名，走「无域名」那一支（§5）。

---

10. **站点筛选折的是主机写法，不是端口**：`localhost` 这一桶含本机所有端口与三种环回写法；想只看某个端口仍得靠关键词（搜 `3000` 能命中写了端口的网址），而 `*.localhost` 这类通配条目仍自成一桶。
