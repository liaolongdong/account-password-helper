个人信息填写演示台

逐个点进下面的框：被识别为个人信息载体的框，下方会出现一枚「这是「××」字段」的气泡，带「从身份库选择 / 收起」两个动作。气泡只报角色，不改写你的输入，也不把值带出这一页。

① 嵌套 label（原生表单最常见写法）

标签把输入框包在中间，分类器走 closest('label') 这一条。本区的电子邮箱与邮政编码进了 username 桶，被 ⑤ 区的登录对判成登录语境，于是归钥匙（data-owns="fill"，口径见页头）。

证件号档额外带一句「请核对后再取用」。

② label[for] + 组件库式兄弟块（Element Plus / Ant Design 的形状）

标签与输入区互为兄弟、input 的 id 是 el-id-… 合成串。这一区就是「有些页面死活看不到提示」的主案发现场： 三条弱线索（嵌套 label / 兄弟文本 / 属性词元）在这里同时落空，只剩 for 这一条显式关联可查。

③ 收货卡：归属三档（本人 / 待核对 / 一定是别人）

「收货人」可能是家属，提示要求核对；「紧急联系人」一定是别人——用本人证件号填别人的框是唯一不可接受的误填，因此整条不出提示。 本区「联系电话」进了手机号桶，被 ⑤ 区的登录对判成登录语境，于是归钥匙不出气泡（data-owns="fill"，口径见页头）。

④ autocomplete 自声明（站点自己把答案写在属性上）

这是最强的一档信号，优先级高于一切词典与守卫；卡类按既有拍板例外，永不进提示路径。本区「电话」与 ③ 区同因归钥匙。

⑤ 登录区块（口令框与凭据词元）

这一区的手机号框分类器仍会给角色，但页面侧要让位给快速填充那把钥匙（data-owns="fill"）， 气泡不出现——它就是让位规则的触发源：这一区的账号+密码对把整页判成登录语境，连带 ③④⑦ 区的桶内框也归钥匙。

⑥ 裸兄弟文本与表格（没有 label 元素的老页面形状）

姓名：<input> 与表格里，标签既不是 label 也不在任何关联属性上，只能按邻居文本退让取值。

⑦ 英文表单

扩展本身中英双语，英文站点漏一整个词典就是整段沉默，所以这一区单独摆出来。本区 Email / Phone 两框同样归钥匙（口径见页头）。

⑧ 值形状收口（标签全没有，只有已输入的值）

最后一层读一次该字段自己的值，判的是「像不像证件号 / 手机号 / 邮箱」，带出去的依据是形状码而不是原文。 第四框把同样的 11 位数字写进 type=password：遮蔽值不参与形状回推，结构性排除排在它前面。

⑨ 负向区：这些框无论如何都不该出提示

元信息与事物名（物品名称 / 证件类型 / 房间数量 / 职业）、搜索容器、隐藏域、上传控件。

⑩ aria-labelledby（标签写在别的节点上）

无障碍写法把标签写在别的节点上，框上只有一个 id 列表；这一区刻意不配 label[for]。
