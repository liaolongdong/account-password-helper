个人信息填写演示台

逐个点进下面的框：被识别为个人信息载体的框，下方会出现一枚「这是「××」字段」的气泡，带「从身份库选择 / 收起」两个动作。气泡只报角色，不改写你的输入，也不把值带出这一页。

① 嵌套 label（原生表单最常见写法）

标签把输入框包在中间，分类器走 closest('label') 这一条。本区的电子邮箱与邮政编码进了 username 桶，被 ⑤ 区的登录对判成登录语境，于是归钥匙（data-owns="fill"，口径见页头）。

证件号档额外带一句「请核对后再取用」。

② label[for] + 组件库式兄弟块（Element Plus / Ant Design 的形状）

标签与输入区互为兄弟、input 的 id 是 el-id-… 合成串。这一区就是「有些页面死活看不到提示」的主案发现场： 三条弱线索（嵌套 label / 兄弟文本 / 属性词元）在这里同时落空，只剩 for 这一条显式关联可查。

③ 收货卡：归属三档（本人 / 待核对 / 一定是别人）

「收货人」可能是家属，提示要求核对；「紧急联系人」一定是别人——用本人证件号填别人的框是唯一不可接受的误填，因此整条不出提示。 本区「联系电话」进了手机号桶，被 ⑤ 区的登录对判成登录语境，于是归钥匙不出气泡（data-owns="fill"，口径见页头）。

④ autocomplete 自声明（站点自己把答案写在属性上）

这是最强的一档信号，优先级高于一切词典与守卫；卡类里只有卡号进提示路径（2026-10-17 拍板）， 有效期与安全码是卡类口令、永不提示。本区「电话」与 ③ 区同因归钥匙。

⑤ 登录区块（口令框与凭据词元）

这一区的手机号框分类器仍会给角色，但页面侧要让位给快速填充那把钥匙（data-owns="fill"）， 气泡不出现——它就是让位规则的触发源：这一区的账号+密码对把整页判成登录语境，连带 ③④⑦ 区的桶内框也归钥匙。

⑥ 裸兄弟文本与表格（没有 label 元素的老页面形状）

姓名：<input> 与表格里，标签既不是 label 也不在任何关联属性上，只能按邻居文本退让取值。

⑦ 英文表单

扩展本身中英双语，英文站点漏一整个词典就是整段沉默，所以这一区单独摆出来。本区 Email / Phone 两框同样归钥匙（口径见页头）。

⑧ 值形状收口（标签全没有，只有已输入的值）

最后一层读一次该字段自己的值，判的是「像不像证件号 / 手机号 / 邮箱」，带出去的依据是形状码而不是原文。 第四框把同样的 11 位数字写进 type=password：遮蔽值不参与形状回推，结构性排除排在它前面。

⑨ 负向区：这些框无论如何都不该出提示

元信息与事物名（物品名称 / 证件类型 / 房间数量 / 职业）、搜索容器、隐藏域、上传控件。

⑩ aria-labelledby（标签写在别的节点上）

无障碍写法把标签写在别的节点上，框上只有一个 id 列表；这一区刻意不配 label[for]。

⑪ 组件库复合表单项（一项两枚控件时，标签拿不到）

用户实机截图那一页的形状。Element Plus 2.14.4 的 form-item 把 labelFor 算成 props.for ?? (inputIds.length === 1 ? inputIds[0] : undefined)——一个表单项里只要有第二枚控件 （类型选择器 + 号码框、起始日期 + 截止日期），for 就不发，标签节点从 <label> 退化成 <div class="el-form-item__label">。必填星号是 CSS 画的 ::before，不占文本，所以「联系方式」四个字就在那一枚 div 里。 号码框这一侧的四条常规线索同时落空： 它不是 label 的后代、for 指在隔壁选择器上、el-input 默认不渲染 name（id 是 el-id-… 合成串）——于是这一框静默没有提示，这区把这一条钉成账本。 四条预算各有对应的行： 块内载体控件 > 2 就当它是整张卡片而不是一个字段（#k-d*）， placeholder 与兄弟标签角色冲突时弃用兄弟标签（#k-x2）， 兄弟标签自身是负向词时同样弃用，那块文字不像在命名时也弃用—— #k-c1 的前兄弟 .el-select__selected-item 写着「手机号码」，那是这一枚下拉当前选中的值， 不是它的名字：当成名字就把类型选择器报成 phone，提示会教用户往「选证件类型」那格里塞证件号。 本区先前把这一行记成 tier="group" 并注为「天然后果」，现按这条反例改判沉默； 号码框 #k-c2 不受影响，它够到的仍是项级标签「联系方式」。 本区与 ⑫⑬ 的 id 写成无意义代号：id 本身就是分类器的信号源， 把答案写进命名（早先那版叫 k-phone）会让一行「不改代码也绿」，账本当场失去牙齿。

⑫ 行栅格（Ant Design 3 的真实形状：标签在兄弟块、input 无 name/id）

这一区的 DOM 不是想象出来的：2026-10-17 对一家银行开户页（etbank.com.cn/#/register）逐框勘察， 88 枚控件里提示 0 枚、钥匙 0 枚，形状就是这里的「ant-col-6 标签块 + ant-col-18 控件块」，且 <label> 不写 for、input 不写 name/id，语义只剩 placeholder。 那页绝大多数条目问的是 机构而不是本人（机构证件号码 / 统一社会信用代码 / 金融业务资质证件号码 / 公司名称 / 注册资本）， 所以这一区同时是「弱线索放大之后会不会误报」的对照表：#k-a4 必须沉默——它没有 for，「机构证件号码」那六个字不在这一格自己的标签或属性上， 闸门因此只拦不判（出口码 orgCredential，同因还有 ⑬ 区的 #k-p15 / #k-p16；把它改成 <label for> 就是 ⑯ 区那两行，判成编号族）， #k-a5 要照常提示成单位名，#k-a6 的项里有省 / 市 / 区县 + 详情四枚载体， 兄弟标签「地址」按一项一义（块内载体 > 2 即视作用区标题）让位给占位符。 #k-a2「证件号码」是这一区最要紧的一行：placeholder 里的「号码」二字会让旧的分桶 把它读成手机号框并挂上钥匙，而钥匙点出来的是账号列表、填不出证件号，所以提示不跟着让位 （页头记了这条改判）。同区的 #k-a3 是组件库代理成 <input readonly> 的日期框，带 data-nohint="readonly"。

⑬ 只有占位符说话（label 全没有，placeholder 是唯一线索）

用户点名要的判据：「检测当前填写的 input 字段或者 placeholder是不是个人信息字段」。 这两条通道排在 name/id 词元与 label 之后——弱信号永不覆盖强信号， 所以 #k-p14（label 写「联系电话」、placeholder 写「请输入邮箱」）报的是 phone 而不是 email。 七条沉默行各守一种误报：验证码与搜索（负向短语先于一切正向词典）、type=password（结构性排除）、 示例式占位符（没有词典短语）、账号语义（name=user_account 的词元守卫——placeholder 说「姓名」也不许把它救回来）、 以及机构主体的证件号码（#k-p15 / #k-p16： 机构字样只写在 placeholder 上，这一格自己没说什么，闸门因此只拦不判）。 剩下三行是钥匙取得出值的那两档： #k-p3 邮箱、#k-p7 手机号、#k-p14 联系电话在这一份文档里都拿到了钥匙， 于是标 data-owns="fill"； #k-p6 是页面回写的只读日期框，标 data-nohint="readonly"。

⑭ 银行卡三档（2026-10-17 拍板放开：卡号 / 户名 / 开户行）

放开的只有这三档，且一律要求身份库复验。有效期 与 CVV 属卡类口令， 识别得到也永不提示。中文「银行账号」这种写法会撞上负向词 账号，为它开的例外与 名称 / 方式 是同一条形状歧义： 裸「账号」是登录名，必须继续沉默。

⑮ 不可输入的控件（分类器照判，页面侧不给提示）

气泡唯一的动作是「把这格填上」，所以只读的框不参与：组件库把日期选择器与下拉代理成 <input readonly>，页面回写的灰底框同理——焦点进得去、键盘打不进。 这几行带 data-nohint="readonly"：data-expect 记的是分类器结论， 真机那条账本据此期望零枚气泡。最后一行是 disabled， 它压根拿不到焦点，因此 FormDetector 刻意不为它写判据。

⑯ 国内五类高频填报场景（社保 / 公租房 / 公积金 / 快递 / 住址）

前十五区按形状分，这一区按业务分：同一套词典放进真实政务与电商表单里， 一句标签到底认不认得。这里的形状都取自用户实测过的页面——社保那张表整张是 table、标签写在 <td> 且一个 placeholder 都没有 （所以六行全钉 data-tier="group"），公租房申请的每条都写成「申请人 + 某个字段」， 而 姓名 在词典里比 证件号码 更早出现——这一区就是那条先后关系的现场。 末两行还是另一条先后关系的现场：社保卡号报证件号（那一串就是本人的社会保障号码， 库里存着它），社保电脑号报 ⑰ 区的 serialNumber（深圳那一串 8 位电脑号不等于身份证号）。词典里「电脑号」档排在证件号档之前， 反序会让含「社保卡」三字的这句被证件号先接走——这一对由 tests/content/piiClassifier.coverage.test.ts 钉住。

⑰ 编号族：库里没有那一格，落点是自定义字段（2026-10-18 拍板）

学历证书编号、教师资格证编号、驾照档案编号、社保电脑号、保单号——每一串都自成一格， 但都不是本人身份证号。把它们提示成「证件号」会把人往身份证号上引，而身份库确实没有为它们准备的字段， 于是这一族由 2026-10-18 新加的 serialNumber 角色接住：它不声称证件号， 气泡在角色之外多一句「可在自定义字段里存下它」，而点「从身份库选择」时深链带的搜索词是 这一格的字段名（不是本人姓名）。落点成立靠的是既有的一条库内行为： 自定义字段的名字和值都参与检索（tests/composables/useIdentityVault.test.ts 钉住）， 所以用户自己建过一格叫「学历证书编号」，提示点下去就把它筛出来。 同一档还接另一族：⑯ 区那两行（机构证件号码 / 统一社会信用代码）自 2026-10-18 起也判成 serialNumber，但它们不从词典进来——由第 3.5 层机构证照闸门 按证据来源改判进来，所以这一区的三张词表里没有机构词，两族的共同点只是「库里没有那一格」。 取值口径与姓名那一族不同：读的是标签文字，永远不读这一框里已经填的值。
