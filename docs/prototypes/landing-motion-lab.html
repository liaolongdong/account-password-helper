安全声明横幅

机制：带 both 的 animation-delay 会把元素按在 opacity: 0 的起始帧，全透明期间它不作为 LCP 候选被记录

现状
index.html:1581-1609：首屏 7 个元素统一 aph-rise 0.6s both，延迟 0.06 / 0.14 / 0.22 / 0.28 / 0.34s（横幅）。.hero-visual 延迟 0.1s、时长 0.7s。
建议
LCP 那一行改成「只位移不淡入」（或时长压到 0.2s 的纯淡入）并把延迟收到 ≤80ms；装饰层与次级文案保留错峰。错峰节奏本身用 --rank 计算（calc(var(--rank) * 70ms)），比手写 5 个 .reveal-delay-N 省维护，与兄弟站同款。
必须实测
这条是机制推断，不是已测结论：本机的 LCP 元素到底是 h1 文字还是 .key-card 渐变块、实际差多少毫秒，要用 chrome-devtools 的 performance_analyze_insight 或 benchmarks/ 跑前后对比， 有数据再动 index.html。
降级
勾选顶部「模拟减弱动效」能看出一个残留问题：左卡（现状写法）的 animation-delay 由 :nth-child 设出，特异度高于末尾降级块，因此在减弱动效下依然要等最长 340ms 才出现——这本身就是要修的一条。 右卡已把延迟一并归零。
成本
低（改既有 Motion layer 的延迟/关键帧引用），但收益是性能口径，不是观感。

影响面
21 个 .reveal 节点，其中 #compare（index.html:2829）是整节隐形； <noscript> 里目前只回退了 FAQ。兄弟站两个落地页都是 html.js .reveal {…} 的写法，本站缺失。
与动效的关系
这是给后续所有动效铺地基：不先做 html.js 门控，加的动效越多，无 JS 场景下被吞掉的内容就越多。
成本
低：一行 document.documentElement.classList.add('js') + 给动效选择器加前缀，或保留现状但补 IO 缺席兜底。
