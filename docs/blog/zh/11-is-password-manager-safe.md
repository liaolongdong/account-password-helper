「把密码交给一个工具存着，真的安全吗？」这是我被问得第二多的问题——第一多的是「为什么填不上」。问的人往往不是开发者，只是想给爸妈、给自己找一个放心的存法。

这篇不堆术语，也不替你拍板买哪个。它只回答三个最朴素的问题：**密码存在哪、谁能读到、丢了怎么办**。把这三件事想清楚，「安不安全」就不再是一个玄学形容词，而是一组你能自己核对的事实。

## 先问一句：你的密码现在存在哪

大多数人从来没认真想过这个问题。常见的答案有三种：

- **记在脑子里或纸上。** 听起来最「安全」，但人的记忆会逼你复用——为了记住，十个网站用同一个密码。一旦其中一家泄露，其余九家跟着遭殃。纸则会丢、会被拍下来。
- **交给浏览器自带管理器。** 方便，登录时点一下「保存」就攒下来了。但开启同步后，这些密码会随你的浏览器账号被托管到厂商的服务器上；关掉同步，它又只活在这一台设备里。
- **交给一个密码管理器。** 数据落在哪、加不加密、要不要联网，取决于这个工具怎么设计。

「存在哪」决定了后面两个问题的答案。所以别急着比功能列表，先把这一格填上。

## 三种存法，攻击面各不一样

安全不是「有没有加密」一句话，而是「在什么情况下，谁有机会读到你的明文」。

**复用是最大的现实风险。** 攻击者很少真的去破解你的加密——他们更常拿别处泄露的账号密码来「撞库」。你重复使用的那个密码，可能早在某次与你无关的数据泄露里躺进了字典。所以「每个网站一个不同的密码」比「密码够不够复杂」更要紧。

**浏览器同步把信任交给了厂商。** 这不是说厂商一定不可信，而是你要清楚：开了同步，密码的副本就离开了你的设备，安全性的一部分由对方的服务器和账号体系承担。你的浏览器账号若被攻破，影响面就不止一台电脑。

**本地优先把信任收回自己手里。** 以 [Account Password Helper](https://github.com/liaolongdong/account-password-helper) 为例，它是一个本地优先的 Chrome 扩展：密码逐字段加密后存在浏览器的 `chrome.storage.local` 里，没有账号、没有同步服务器。数据要不要离开这台设备，由你决定，而不是默认行为。代价是跨设备得靠自己导出导入——这是「控制权」和「省事」之间的取舍，没有免费午餐。

## 加密到底在保护什么

很多人以为「加密」就是给整个库套一把锁。更细的做法是**字段级加密**：每条记录的账号、密码、网址、备注、动态口令各自单独加密后再写进浏览器的 `chrome.storage.local`；标签和时间戳仍是明文，因为列表要靠它们排序和筛选。所以从磁盘上读不到明文密码，但也不是什么都读不到。解密只发生在你解锁后的会话里，一旦锁定或会话过期，内存中的明文随即清空。

这里有两个普通人也该知道的常识：

**主密码不是直接当钥匙用的。** 它先经过一个叫 PBKDF2 的密钥派生函数，做 60 万次迭代才变成真正的加密密钥。这一步的意义是：哪怕有人拿到了你的密文文件，想靠「猜主密码」逐个试，每一次猜测都要付出 60 万次运算的成本，暴力破解因此变得不划算。这也是为什么主密码可以是一句好记的长口令，而不必是一串反人类的乱码——长度比花样更重要。

**加密保护的是「静态数据」。** 它防的是别人拿到你的存储文件后读不出明文。它不防你正在用的这台电脑本身被恶意软件控制，也不防你解锁状态下被人凑到屏幕前。所以「加密很强」和「绝对安全」是两回事，下一节就讲这个边界。

## 本地优先不是万能药：它不替你挡什么

诚实地划清边界，比喊口号更有用。一个本地密码管理器**不能**替你做到这些：

- **它不防钓鱼。** 你把主密码或某条密码亲手填进了一个假网站，加密再强也拦不住。工具能帮你按域名匹配、减少填错站的概率，但最终按下提交的是你。
- **它不防设备被控。** 如果你的电脑已经中了键盘记录或远程控制，解锁后的明文就在内存里，任何本地工具都无力回天。
- **它不防主密码太弱。** 60 万次迭代抬高的是「每次猜测」的成本，抬不高一个 `123456` 本身的信息量。主密码得够长、够独特。
- **它不替你备份。** 本地优先意味着数据主要活在你这台设备上。设备坏了、浏览器数据被清，没有备份就真没了。导出加密备份是你自己的责任。

把这些「不防」记在心里，你就不会把任何一个工具当成保险箱供起来。

## 丢了怎么办：备份与恢复

本地优先的便利和风险是同一枚硬币。既然没有云端替你兜底，**定期导出一份加密备份**就是必做项，而不是可选项。

好的备份应当满足三点：备份文件本身是加密的（拿到文件也读不出明文）、恢复时需要你的主密码（而不是任何拿到文件的人都能还原）、并且你把它放在了一个与日常设备分离的地方。这样设备故障时你能恢复，设备被盗时别人又用不了那份备份。

顺带说一句：导出成明文 CSV 表格是另一回事——那是为了迁移到别的工具，文件里的密码是直接可读的，用完应当尽快删掉，别拿它当长期备份。

## 给普通人的五条判断清单

不想读原理，照这五条做也能把风险压到很低：

1. **每个网站用不同的密码。** 这一条的收益超过其余所有花哨功能。让生成器替你随机生成，别自己重复使用。
2. **主密码用一句长口令。** 四五个不相关的词拼起来，比 `P@ssw0rd!` 这种短而「复杂」的更难猜，也更好记。
3. **重要的账号开两步验证。** 密码之外再加一道（验证码、TOTP 或硬件密钥），密码泄露了也还有一层。
4. **定期导出加密备份，放在别处。** 本地优先的工具尤其要养成这个习惯。
5. **想清楚同步这件事。** 要跨设备省事，就接受数据托管给厂商；要数据留在本机，就接受手动迁移。两者都行，别在不知情的情况下默认了其中一种。

安全不是一次性的购买决策，而是一组日常习惯。工具能帮你把这几件事做得更顺手，但按下「保存」和「提交」的，始终是你自己。
