1. 必须使用wxt + vue3 + typescript + element-plus + vite等技术栈开发浏览器插件，使用的技术栈必须是最新的稳定版本，且需按需引入，防止项目打包体积过大。
2. 生成的代码必须要有较强的可维护性、可扩展性、可复用性，重复代码、公共方法和组件必须抽离复用，必须遵循良好的设计模式，必须符合这些技术栈的最佳编码实践，注释代码必须符合JSDoc注释文档规范。
3. 每次完成功能开发或者修复bug后，必须进行代码审核，确保代码质量，禁止因为优化或者修复问题，引入新问题，禁止影响存量功能和交互，保持代码的一致性和可维护性，必须执行自动化验证测试。
4. 必须使用ESLint + Prettier进行代码格式化和静态代码分析，确保代码风格一致性和可读性。
5. 文件引入规则，除了同级目录的文件使用`./`引入，其它引入的本地文件，必须使用`@/`开头，如果这种引入方式未配置，则在构建工具配置支持。
6. 日志打印必须使用`utils/logger.ts`封装的日志方法，禁止直接使用`console`。
7. 项目已配置 husky + lint-staged，提交代码前会自动运行 ESLint + Prettier + Stylelint 检查变更文件，必须确保提交前通过所有检查。
8. ESLint 配置全面覆盖 TypeScript 和 Vue 文件，新增代码必须通过 `npm run lint` 检查，禁止使用 `eslint-disable` 规避规则（logger.ts 等底层封装除外）。
9. CSS/Stylelint 已启用属性排序（recess-order），新增样式代码必须符合属性顺序规范。
10. 新增功能必须同步考虑中英文国际化，同时必须更新和完善四处文档（README / index.html / HelpDialog / CWS）、`wxt.config.ts`插件描述等相关文档描述信息。
11. 优化改动的代码，特别是大文件拆分、重复代码抽离复用、组件抽离封装、ts类型定义抽离、公共方法封装、变量提取等，特别要求：在不影响原有功能和交互体验的情况下进行优化，如果涉及影响功能和交互体验的优化，必须停下来询问确认。
12. 对改动的代码进行代码评审，确保改动的代码不影响原有功能和交互体验，特别是打开侧边栏的性能。
